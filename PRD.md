Документ 1: PRD.md (Product Requirements Document)
1. Обзор продукта (Product Overview)
Название проекта (рабочее): ContentForge / Social Engine

Суть продукта: Веб-приложение для быстрой генерации структурированного контента под конкретные площадки (Telegram, YouTube, Instagram) через Google Gemini API. Приложение решает проблему «белого листа»: пользователь вводит сырую идею или описание бизнеса, выбирает платформу и в реальном времени получает несколько готовых к публикации вариантов поста с четкой структурой и сохранением в историю.

2. Целевая аудитория и сценарии использования (Use Cases)
Авторы Telegram-каналов и блогеры: Быстрый драфт постов из коротких заметок или инфоповодов.

SMM-специалисты и владельцы малого бизнеса: Адаптация одного оффера или описания услуги под разные форматы (пост в ТГ, описание к Reels/посту в Instagram, описание и заголовки для YouTube-ролика).

Инди-мейкеры и разработчики: Генерация анонсов релизов, апдейтов и обучающего контента.

3. Функциональные требования (Functional Requirements)
3.1. Ввод данных и настройка генерации
Поле ввода (Prompt Input): Многострочное текстовое поле для ввода темы, описания бизнеса, сырой идеи или тезисов (с подсчетом символов и горячей клавишей отправки Ctrl/Cmd + Enter).

Выбор платформы: Переключатель (Single Select) между тремя площадками:

Telegram: Акцент на читаемость, абзацы, уместное форматирование, вовлекающий вопрос в конце.

Instagram: Визуально легкий текст для Reels/каруселей, хук в первой строке, блок релевантных хэштегов.

YouTube: Кликбейтный/SEO-заголовок, структурированное описание к видео/Shorts, таймкоды-заглушки (опционально), теги.

Количество вариантов: Выбор генерации от 2 до 3 вариантов за один запрос для A/B-выбора (по умолчанию — 3 варианта с разными углами подачи: например, «Экспертный/Прямой», «Сторителлинг/Кейс», «Провокационный/Короткий»).

3.2. Прегенерация (Smart Pre-generation & Context Enrichment)
Перед отправкой тяжелого основного запроса система выполняет быстрый предварительный шаг (или фоновый пре-фетч при паузе ввода / клике на кнопку «Улучшить контекст»):

Автоматическое определение недостающих деталей в промпте и генерация 3 быстрых тегов-уточнений (например, выбор тональности, целевого действия или угла подачи), которые можно кликом добавить к запросу.

Либо мгновенная генерация скелета/тезисов (хуков) за 0.5–1 секунду до старта основного потока, чтобы пользователь сразу видел направление мысли ИИ.

3.3. Генерация и структура ответа
Каждый сгенерированный вариант должен строго делиться на 4 визуально и логически отдельных блока:

Заголовок (Headline / Hook): Первая цепляющая фраза или название ролика.

Основной текст (Body): Отформатированный под правила выбранной соцсети текст.

Призыв к действию (CTA): Четкий триггер на комментарий, подписку, переход по ссылке или сохранение.

Хэштеги (Hashtags): Набор релевантных тегов без спама.

3.4. Постепенный вывод текста (Streaming UI)
Использование Server-Sent Events (SSE) или потокового чтения ответа от Gemini API (generateContentStream).

Текст появляется плавно по мере генерации токенов без блокировки интерфейса.

Пользователь видит, как заполняются карточки вариантов в реальном времени.

3.5. Взаимодействие с результатом (Copy & Edit)
Копирование в 1 клик (One-click Copy):

Кнопка «Скопировать всё» (собирает Заголовок + Текст + CTA + Хэштеги с правильными отступами в буфер обмена).

Возможность скопировать отдельный блок (например, только текст или только хэштеги) по клику на него.

Мгновенный визуальный фидбек при копировании (смена иконки/текста кнопки на 1.5 секунды без назойливых всплывающих окон на пол-экрана).

3.6. История постов (Post History)
Автоматическое сохранение каждого успешного результата генерации.

Фильтрация истории по соцсети (Все / Telegram / YouTube / Instagram) и быстрый текстовый поиск по теме.

Возможность открыть прошлую генерацию, скопировать любой из вариантов или удалить запись из истории.

4. Нефункциональные требования (Non-Functional Requirements)
Отзывчивость (Latency): Время до первого токена (TTFT) при стриминге — обычно не более 0.8–1.5 сек.

Надежность парсинга: Потоковый ответ не должен ломать верстку карточек во время генерации.

Приватность и скорость работы истории: Мгновенная загрузка истории при открытии приложения без долгих спиннеров.
